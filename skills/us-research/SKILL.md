# Evidence before implementation planning

Load `skill://us-concise`. Apply lane selection in `skill://us-workflow` before composing automatic stages, including on direct loading. Research is read-only reconnaissance, not code, a plan, or approval. An eligible focused repair still requires current source/caller inspection but no automatic scout or full research cycle merely because `research` is enabled. Select this stage for concrete uncertainty or an independent request. Disabled/unknown research is not automatically selected; essential inspection remains the parent's duty.

## Inputs

Start with the requested behavior, known constraints, the current checkout, and any existing plan/todo/transcript that may describe prior work. Recheck important historical claims against current source.

## Procedure

1. Perform a bounded initial scope read: locate the likely implementation, callers, tests, configuration, project guidance, and relevant documentation. Follow actual data/control flow rather than isolated snippets.
2. When memory actions are applicable in normal composition or selected for concrete focused-repair memory impact, load `skill://us-memory` and follow only the corresponding eligible **During research** actions. Enabled memory settings alone do not force focused memory calls. If neither action is eligible/selected, make no automatic memory call (including `status`); explicit memory requests remain independent. Unavailable memory does not block source inspection.
3. Before a required dispatch, load the **Native model routing** guidance in `skill://us-workflow`; loading that guidance does not launch the workflow. Ordinary installed startup supplies the narrowly scoped session-local policy for an enabled research stage; use only the active session workspace and do not select a repository globally. The policy does not authorize unrelated delegation or override stronger safety constraints, existing mappings, permissions, approval, or publication boundaries.

4. Dispatch one read-only reconnaissance worker after initial scope inspection when research is applicable and enabled in normal composition, selected and eligible for a focused repair, or a worker is independently required. Use native `scout` only if advertised; otherwise use the advertised general-purpose worker only when stronger host policy permits. Give it `skill://us-research/references/scout-brief.md`, bounded evidence, and the research question. The worker reports source/callers, conventions, evidence, and uncertainty; it does not edit, plan, or launch a workflow.
5. Compare worker findings with source. Resolve disagreements by tracing current code. Identify existing reusable patterns, constraints, dependencies, affected interfaces, behavioral checks, and risks.

## Completion evidence

Return exact paths/symbols, caller/test relationships, conventions/docs, observed outcomes or skipped status for applicable memory actions, affected interfaces, verification candidates, and uncertainties. The brief informs a plan only when selected or applicable; it does not require one or imply approval. Do not call omitted stages completed.

## Failure behavior

A missing graph, native memory backend, or worker does not block source research. Record the exact unavailable capability and complete all reachable source inspection. Do not invent worker findings or infer behavior from stale memory. Dependency/cache writes, when permitted, belong only to the explicit actions described in `skill://us-memory`.
